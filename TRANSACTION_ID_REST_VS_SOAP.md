# Transaction ID: REST vs SOAP

This document explains the differences between transaction ID implementation for REST and SOAP requests.

## 🎯 Quick Summary

Both REST and SOAP support transaction ID tracking, but they use **different mechanisms** to pass the transaction ID:

| Aspect | REST | SOAP |
|--------|------|------|
| **Header Name** | `X-Transaction-ID` | `TransactionId` |
| **Location** | HTTP Header (transport layer) | SOAP XML Header (application layer) |
| **Handler Component** | `TransactionIdFilter` | `SoapTransactionIdInterceptor` |
| **Namespace** | N/A | `http://example.com/headers` |
| **Example** | `-H "X-Transaction-ID: abc-123"` | `<hdr:TransactionId>abc-123</hdr:TransactionId>` |

---

## 📝 Detailed Explanation

### REST Requests - HTTP Header

**REST uses standard HTTP headers** because REST is HTTP-native and follows HTTP conventions.

**Example REST Request:**
```http
POST /api/calculator/add?a=10&b=5 HTTP/1.1
Host: localhost:8080
X-Transaction-ID: REST-TXN-12345    ← HTTP Header (transport layer)
Content-Type: application/json
```

**How it works:**
1. `TransactionIdFilter` (Servlet Filter) intercepts the HTTP request
2. Extracts `X-Transaction-ID` from HTTP headers
3. If not present, generates a new UUID
4. Adds to MDC for logging
5. Adds to HTTP response header for downstream services

**Testing REST with Transaction ID:**
```powershell
# PowerShell
$headers = @{ "X-Transaction-ID" = "REST-TXN-12345" }
Invoke-RestMethod -Uri "http://localhost:8080/api/calculator/add?a=10&b=5" -Headers $headers

# curl
curl -H "X-Transaction-ID: REST-TXN-12345" http://localhost:8080/api/calculator/add?a=10&b=5
```

---

### SOAP Requests - SOAP Header (XML)

**SOAP uses SOAP headers** because SOAP is XML-based and follows the SOAP specification.

**Example SOAP Request:**
```http
POST /services/Calculator HTTP/1.1
Host: localhost:8080
Content-Type: text/xml
                                     ← No X-Transaction-ID in HTTP headers!

<soapenv:Envelope xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/" 
                  xmlns:cal="http://example.com/calculator"
                  xmlns:hdr="http://example.com/headers">
   <soapenv:Header>
      <hdr:TransactionId>SOAP-TXN-12345</hdr:TransactionId>    ← Inside XML (application layer)
   </soapenv:Header>
   <soapenv:Body>
      <cal:add>
         <cal:a>10</cal:a>
         <cal:b>5</cal:b>
      </cal:add>
   </soapenv:Body>
</soapenv:Envelope>
```

**How it works:**
1. `TransactionIdFilter` intercepts HTTP request first (may generate initial UUID)
2. `SoapTransactionIdInterceptor` (CXF Interceptor) parses SOAP envelope
3. Extracts `<TransactionId>` from SOAP Header section
4. If found, **overwrites** the MDC value with the SOAP header value
5. If not found, keeps the UUID generated by the filter
6. All subsequent logs use the final MDC value

**Testing SOAP with Transaction ID:**
```powershell
$soapRequest = @"
<soapenv:Envelope xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/" 
                  xmlns:cal="http://example.com/calculator"
                  xmlns:hdr="http://example.com/headers">
   <soapenv:Header>
      <hdr:TransactionId>SOAP-TXN-12345</hdr:TransactionId>
   </soapenv:Header>
   <soapenv:Body>
      <cal:add>
         <cal:a>10</cal:a>
         <cal:b>5</cal:b>
      </cal:add>
   </soapenv:Body>
</soapenv:Envelope>
"@

Invoke-WebRequest -Uri "http://localhost:8080/services/Calculator" -Method POST -ContentType "text/xml" -Body $soapRequest
```

## 🔄 Request Processing Flow

### REST Request Flow
```
1. HTTP Request arrives with X-Transaction-ID header
   ↓
2. TransactionIdFilter extracts/generates transaction ID
   ↓
3. Adds to MDC: MDC.put("transactionId", "REST-TXN-12345")
   ↓
4. REST Controller processes request
   ↓
5. All logs show: [REST-TXN-12345]
   ↓
6. Response includes X-Transaction-ID header
```

### SOAP Request Flow
```
1. HTTP Request arrives (POST /services/Calculator)
   ↓
2. TransactionIdFilter generates initial UUID
   MDC.put("transactionId", "uuid-abc-123")
   ↓
3. SoapTransactionIdInterceptor parses SOAP XML
   Finds: <hdr:TransactionId>SOAP-TXN-12345</hdr:TransactionId>
   ↓
4. Overwrites MDC: MDC.put("transactionId", "SOAP-TXN-12345")
   ↓
5. SOAP Service processes request
   ↓
6. All logs show: [SOAP-TXN-12345]
   ↓
7. Filter's completion log uses final MDC value
```

## 🤔 Why Two Different Approaches?

### REST Uses HTTP Headers Because:
- ✅ REST is HTTP-native
- ✅ Simple key-value pairs
- ✅ Easy to add with any HTTP client
- ✅ Follows HTTP/REST conventions
- ✅ Widely supported by HTTP libraries

### SOAP Uses SOAP Headers Because:
- ✅ Part of SOAP specification
- ✅ Structured XML with namespaces
- ✅ Can have complex types and attributes
- ✅ SOAP clients expect headers in XML
- ✅ HTTP headers might not be accessible to all SOAP toolkits
- ✅ Allows for WS-* standards compliance

---

## 💡 Common Goals, Different Implementations

Despite different mechanisms, both achieve:

✅ **End-to-end request tracking** across microservices
✅ **Automatic logging** with transaction ID in all log entries
✅ **Correlation** of all operations for a single request
✅ **Debugging** by filtering logs by transaction ID
✅ **Distributed tracing** across service boundaries

## 🔧 Implementation Components

### For REST Requests
**File**: `src/main/java/com/example/cxf/filter/TransactionIdFilter.java`

**Key Code:**
```java
@Component
@Order(1)
public class TransactionIdFilter implements Filter {
    private static final String TRANSACTION_ID_HEADER = "X-Transaction-ID";
    
    @Override
    public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain) {
        // Extract from HTTP header
        String transactionId = httpRequest.getHeader(TRANSACTION_ID_HEADER);
        
        // Add to MDC
        MDC.put(TRANSACTION_ID_MDC_KEY, transactionId);
        
        // Add to response header
        httpResponse.setHeader(TRANSACTION_ID_HEADER, transactionId);
    }
}
```

### For SOAP Requests
**File**: `src/main/java/com/example/cxf/interceptor/SoapTransactionIdInterceptor.java`

**Key Code:**
```java
@Component
public class SoapTransactionIdInterceptor extends AbstractSoapInterceptor {
    private static final String TRANSACTION_ID_HEADER = "TransactionId";
    private static final String NAMESPACE = "http://example.com/headers";
    
    public SoapTransactionIdInterceptor() {
        super(Phase.PRE_PROTOCOL);
    }
    
    @Override
    public void handleMessage(SoapMessage message) {
        // Extract from SOAP header
        List<Header> headers = message.getHeaders();
        for (Header header : headers) {
            if (TRANSACTION_ID_HEADER.equals(header.getName().getLocalPart())) {
                Element element = (Element) header.getObject();
                String transactionId = element.getTextContent();
                
                // Add to MDC (overwrites if already set)
                MDC.put(TRANSACTION_ID_MDC_KEY, transactionId);
            }
        }
    }
}
```

## 🎯 Best Practices

### For REST Clients
```java
// Java RestTemplate
HttpHeaders headers = new HttpHeaders();
headers.set("X-Transaction-ID", "my-transaction-123");
```

```javascript
// JavaScript fetch
fetch('http://localhost:8080/api/calculator/add?a=10&b=5', {
    headers: {
        'X-Transaction-ID': 'my-transaction-123'
    }
});
```

### For SOAP Clients
```xml
<!-- Always include namespace -->
<soapenv:Envelope xmlns:hdr="http://example.com/headers">
   <soapenv:Header>
      <hdr:TransactionId>my-transaction-123</hdr:TransactionId>
   </soapenv:Header>
   <soapenv:Body>...</soapenv:Body>
</soapenv:Envelope>
```

```java
// Java CXF Client
QName transactionIdQName = new QName("http://example.com/headers", "TransactionId");
Header header = new Header(transactionIdQName, "my-transaction-123", new JAXBDataBinding(String.class));
((BindingProvider) port).getRequestContext().put(Header.HEADER_LIST, Arrays.asList(header));
```

## ✅ Quick Checklist

**For REST API Consumers:**
- [ ] Include `X-Transaction-ID` HTTP header
- [ ] Use the same ID when calling downstream services
- [ ] Check response for `X-Transaction-ID` header

**For SOAP API Consumers:**
- [ ] Include `<hdr:TransactionId>` in SOAP Header
- [ ] Use correct namespace: `http://example.com/headers`
- [ ] Declare namespace prefix in Envelope
- [ ] Pass same ID to downstream SOAP services

**Both approaches ensure complete observability and request tracing! 🎉**
